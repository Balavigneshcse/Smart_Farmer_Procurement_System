# Deploying (M8): Render + Neon + Brevo, all free

The app runs as a Docker container on **Render**, the database is **Neon** PostgreSQL, and emails go
through **Brevo** (Render's free plan blocks SMTP, so Gmail cannot be used there).
Total cost: nothing. You need three free accounts; the steps below take about 20 minutes.

## 1. Neon (database)

1. Sign up at <https://neon.tech> and create a project: name `smart-farmer`, PostgreSQL 17 or 18,
   region **Asia Pacific (Singapore)**.
2. On the dashboard click **Connect** and choose **Java** (JDBC). You get three values:
   - `DB_URL` = `jdbc:postgresql://ep-....ap-southeast-1.aws.neon.tech/neondb?sslmode=require`
   - `SPRING_DATASOURCE_USERNAME` = the user (e.g. `neondb_owner`)
   - `SPRING_DATASOURCE_PASSWORD` = the password

The tables are created by Flyway on the first start; there is nothing to run by hand.

## 2. Brevo (emails)

1. Sign up at <https://www.brevo.com> (free plan: 300 emails a day).
2. **Senders, domains & IPs → Senders → Add a sender** with the email address the app should send from,
   and confirm it from the email Brevo sends you. That address is `MAIL_FROM`.
3. **SMTP & API → API keys → Generate a new API key**. That is `BREVO_API_KEY`
   (shown once; paste it straight into Render).

## 3. Render (the app)

1. Sign up at <https://render.com> with your GitHub account.
2. **New → Blueprint**, pick the `Smart_Farmer_Procurement_System` repository. Render reads
   `render.yaml` and asks for the values below. `JWT_SECRET` and `PAYOUT_ENCRYPTION_KEY` are generated by Render.

| Key | Value |
|---|---|
| `DB_URL`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD` | from Neon (step 1) |
| `SUPERADMIN_USERNAME`, `SUPERADMIN_PASSWORD` | the super admin login for the live site (use a strong password) |
| `BREVO_API_KEY`, `MAIL_FROM` | from Brevo (step 2) |
| `APP_URL` | the Render address, e.g. `https://smart-farmer-procurement.onrender.com` (links and QR pictures in emails use it). You see it at the top of the service page; if you only know it after the first deploy, set it then and press **Manual Deploy**. |
| `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET` | your Razorpay **test** keys (`rzp_test_...`) |

3. **Apply**. The first build takes about 5 to 8 minutes. The service is ready when its log shows
   `Started ProcurementApplication` and `Super admin account ... created`.

### Free plan behaviour
- The service sleeps after 15 minutes without visitors; the next visit wakes it in about a minute.
  Open the site a few minutes before a demo.
- `PAYOUT_ENCRYPTION_KEY` must never change: bank details saved with it could not be read any more.

## 4. After the first deploy

1. Log in at `/staff/login.html` with the super admin.
2. **Admins & staff**: add one admin and one staff account per centre (or more centres first under
   **Centres & crops**). The accounts from `staff-accounts.xlsx` exist only on your PC's database.
3. For a demo: **Dashboard → Load demo day** fills every centre with a busy day.

## 5. Smoke test on the live site

| Check | Expected |
|---|---|
| `https://…onrender.com/actuator/health` | `{"status":"UP"}` |
| Home page | Centres and rates load; language and theme buttons work |
| Farmer login with a real email | OTP email arrives (Brevo) |
| Registration with bank or UPI details, then book a slot | Confirmation email with the QR picture |
| Staff login as a centre's staff account, check in the token, call, weigh | Live queue on the farmer's booking page |
| Admin → Payments → Pay with UPI `success@razorpay` | Status Paid, "payment credited" email |
| `/display.html?centre=1` | TV board updates live |

## 6. Updating the live site
Push to `main` on GitHub. Render rebuilds and redeploys automatically (Auto-Deploy is on by default).
